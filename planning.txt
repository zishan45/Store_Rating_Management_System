STORE RATING MANAGEMENT SYSTEM
PROJECT PLANNING

1. PROJECT OBJECTIVE
--------------------
The objective of this project is to develop a full-stack Store Rating Management System where users can view stores and submit ratings, store owners can monitor ratings for their stores, and administrators can manage users and stores.

The system will provide secure authentication, role-based authorization, store management, and rating management.

3. USER ROLES
-------------
The application will have three types of users:

A. SYSTEM ADMINISTRATOR
- Login securely
- View and manage users
- Create and manage stores
- View store information
- View user information
- Access administrator dashboard

B. STORE OWNER
- Login securely
- View owned store
- View ratings received by the store
- View average store rating
- Monitor customer ratings

C. NORMAL USER
- Register and login
- View available stores
- Search/browse stores
- Submit a rating from 1 to 5
- Update an existing rating
- View rating information


4. MAIN MODULES
---------------
The project will be divided into the following modules:

1. Authentication Module
   - User registration
   - User login
   - Password hashing
   - JWT token generation
   - Authentication middleware

2. User Management Module
   - Create users
   - View users
   - Manage user roles
   - View user details

3. Store Management Module
   - Create stores
   - View stores
   - Assign stores to owners
   - Manage store information

4. Rating Management Module
   - Submit ratings
   - Update ratings
   - View ratings
   - Calculate average store rating

5. Authorization Module
   - Role-based access control
   - Protect admin routes
   - Protect owner routes
   - Protect user routes


5. DATABASE PLANNING
--------------------
The database will be named:

store_rating_db

The main tables will be:

A. users
- id
- name
- email
- password
- address
- role
- created_at
- updated_at

B. stores
- id
- name
- email
- address
- owner_id
- created_at
- updated_at

C. ratings
- id
- user_id
- store_id
- rating
- created_at
- updated_at

Relationships:

- One owner can own one or more stores.
- One user can submit ratings for multiple stores.
- One store can receive ratings from multiple users.
- A user can have only one rating for a particular store.
- Ratings will be restricted to values from 1 to 5.

8. AUTHENTICATION FLOW
----------------------
1. User enters email and password.
2. Backend validates the credentials.
3. Password is verified against the stored hashed password.
4. Backend generates a JWT token.
5. Token is returned to the frontend.
6. Frontend stores the authentication information.
7. Protected API requests include the JWT token.
8. Backend verifies the token before allowing access.


9. RATING FLOW
--------------
1. User logs into the system.
2. User views available stores.
3. User selects a store.
4. User submits a rating from 1 to 5.
5. Backend validates the rating.
6. Rating is stored in the ratings table.
7. Store's rating information is displayed.
8. If the user has already rated the store, the existing rating can be updated.
